# Shared-Kernel Beginner Guide

## 1. shared-kernel은 무엇인가요

`shared-kernel`은 여러 서비스(모듈)들이 서로 대화할 때 사용하는 '공통어 사전'이나 '최소한의 공용 부품 상자'라고 보면 됩니다. 전체 시스템의 뼈대와 규칙을 잡아줍니다.

## 2. 초보자를 위한 개념 설명 (Beginner's Concept Explanation)

- **공통어 사전 (Shared-Kernel)**: 한국인과 미국인이 서로 대화하려면 번역기가 필요하듯, 서로 다른 모듈이 소통하려면 '공통된 기준'이 필요합니다. 예를 들어 '계정 상태'를 A모듈은 1, B모듈은 'ACTIVE'라고 부르면 혼란스럽습니다. 이를 하나로 통일해 놓은 곳이 바로 이곳입니다.
- **바운디드 컨텍스트 (Bounded Context)**: 커다란 회사를 부서(인사부, 재무부, 영업부)로 나누는 것과 같습니다. 서로 다른 업무 영역을 확실히 나누어 선을 그어주는 개념입니다.
- **헥사고날 아키텍처 (Hexagonal Architecture)의 포트/어댑터용 공통 타입**: 각 모듈이 외부와 통신할 때 사용하는 공통 인터페이스, 응답 형식, 또는 ID 식별자(Value Object)의 기본 뼈대를 제공합니다.
- **마스킹 (Masking)**: 고객의 주민번호나 이메일 같은 민감한 정보를 '1234**'처럼 화면이나 로그에서 별표 처리해 가려주는 보호 장치입니다.

## 3. 핵심 아키텍처 가이드라인 (최신 스택 반영)

`shared-kernel`은 다음과 같은 최신 아키텍처 원칙을 시스템 전체에 전파하는 역할을 합니다.

- **헥사고날 아키텍처 지원**: 각 모듈이 참조해야 하는 최상위 인터페이스(예: 공통 유스케이스 형식, 에러 응답 객체 포맷)를 제공합니다.
- **ID 기반 참조 (ID-based Reference)**: 시스템 결합도를 낮추기 위해, 모듈 간에는 객체를 통째로 넘기지 않고 `UserId`, `AccountId` 같은 원시 타입 래퍼(Value Object) 혹은 식별자만 넘기도록 유도하는 공통 식별자 타입을 정의할 수 있습니다.
- **Multi-stage Docker 환경을 위한 메타데이터**: 컨테이너 환경에서 각 서비스가 스스로를 식별하고(Service Discovery), 헬스 체크나 라우팅을 할 수 있게 돕는 메타 정보를 가지고 있습니다.

## 4. 핵심 구성 요소

### `BoundedContext`
이 시스템의 커다란 '부서' 목록입니다. 
- 예: `MASTER_DATA`, `JOURNAL_LEDGER`, `LOAN`, `REPORTING`

### `ServiceCapability`
이 서비스가 외부에 당당하게 "나는 이런 걸 할 줄 알아요!"라고 선언하는 기능 목록입니다.
- 예: `SOURCE_DOCUMENT_LOOKUP` (증빙 조회 기능)

### `ServiceDescriptor`
서비스를 소개하는 요약 명함입니다. (이름, 소속 부서, 할 줄 아는 것)

### `@Masked`
민감 정보에 붙이는 보안 딱지입니다. 이 딱지가 붙은 데이터는 JSON으로 변환되거나 로그에 찍힐 때 지정된 규칙에 따라 별표(`*`) 처리됩니다.

## 5. 기억할 점

- 이 모듈은 **최대한 가벼워야** 합니다.
- 여기에는 복잡한 비즈니스 로직(예: 이자 계산, 재무제표 산출)이 절대 들어가면 안 됩니다.
- 모든 모듈이 이 `shared-kernel`을 의존하므로, 여기를 함부로 변경하면 시스템 전체에 큰 영향을 줄 수 있습니다.
