# governance 초보자 가이드 (Beginner Guide)

`governance` 모듈은 회계 플랫폼의 "감사, 통제, 승인"을 담당합니다. "누가 무엇을 했는지 남기고, 누가 무엇을 할 수 있는지 통제하고, 중요한 변경은 승인받게 만드는" 역할을 합니다. 이 모듈은 헥사고날 아키텍처로 설계되어 다른 모듈에 강하게 결합되지 않고 이벤트를 수신하거나 API를 제공하는 방식으로 작동합니다.

## 🌟 초보자를 위한 개념 설명

* **감사 로그 (Audit Log):** 비행기의 블랙박스입니다. 누가 언제 어떤 화면에서 어떤 버튼을 눌렀고, 그 결과 데이터가 어떻게 변했는지 빠짐없이 기록합니다. 나중에 문제가 생겼을 때 원인을 찾는 핵심 자료가 됩니다.
* **직무 분리 (SOD, Segregation of Duties):** "내가 기안하고 내가 결재할 수 없다"는 원칙입니다. 돈과 관련된 중요한 권한이 한 사람에게 집중되어 사고가 나는 것을 막기 위한 통제 장치입니다.
* **마스터 승인 (Master Approval):** 계정과목이나 거래처 같은 중요한 기준정보를 바꿀 때, 즉시 반영되지 않고 누군가의 허락을 받도록 중간에 안전장치를 두는 것입니다.
* **데이터 마스킹 (Data Masking):** 주민등록번호나 이메일 같은 개인정보를 화면이나 로그에 보여줄 때 `990101-1******` 처럼 일부를 별표로 가리는 기능입니다.

## 주요 역할 분담 (auth vs governance)

- **auth 모듈의 책임:** 로그인, 비밀번호 확인, 메뉴 접속 권한 부여 등 일반적인 IAM(Identity and Access Management).
- **governance 모듈의 책임:** 내부회계 관리제도에 따른 통제 정책 적용, SOD 점검, 변경 이력 감사 로그 작성 등.

## 주요 기능

1. **감사로그 자동 기록:** AOP를 통해 주요 변경 발생 전/후 데이터를 자동으로 비교하여 기록합니다.
2. **승인 파이프라인 관리:** 상태(`PENDING` -> `APPROVED` / `REJECTED`) 변화를 통해 마스터 데이터 변경 등을 통제합니다.
3. **데이터 마스킹:** 개인정보 보호법 준수를 위해 중요 정보를 로그와 API 응답에서 마스킹 처리합니다.

## 헥사고날 아키텍처 및 ID 참조 기반 접근

- 외부 시스템이나 모듈(예: 사용자 정보, 대상 엔티티)을 기록할 때 엔티티를 직접 연결하지 않습니다. 대상 시스템의 문자열 ID(`target_id`)와 대상 타입명(`target_entity`)만 문자열로 저장합니다.
- 감사 이력 조회 시 ID를 기반으로 필요 시 해당 모듈의 조회 포트를 호출하여 상세 내역을 엮어서(Tracing) 보여줍니다.
- 멀티 스테이지 Docker 환경에서 `governance` 컨테이너는 로그 수집과 통제 정책 평가를 독립적으로 수행할 수 있습니다.

## 주요 API

* `GET /api/audit/logs` : 전체 감사 로그 조회
* `POST /api/audit/approvals/requests` : 마스터 데이터 등 승인 요청 등록
* `POST /api/audit/approvals/{approvalId}/approve` : 승인 처리 (이 때 내부적으로 직무 분리 통제를 체크함)
