# Contracts 모듈 (통신 규약집)

## 📌 왕초보를 위한 개념 설명

> **Q. `contracts` 모듈이 대체 뭔가요?**  
> 쉽고 간단하게 말해서, **"서로 다른 부서(서비스)들이 서로 대화할 때 쓰는 공용 서식지"** 입니다.
>
> 🏢 은행에 가서 대출 업무를 본다고 상상해 보세요. 대출 창구 부서(`loan` 모듈)가 회계 부서(`journal-ledger` 모듈)에게 **"이 100만 원, 회계 장부에 좀 이체 기록으로 적어주세요!"**라고 부탁을 해야 합니다.
> 이때, 포스트잇에 아무렇게나 대충 글씨를 휘갈겨서 주면 회계 부서가 알아볼 수 있겠어요? 당연히 에러가 나거나 업무에 차질이 생기겠죠.
> 
> 그래서 은행장님(아키텍트)이 강력하게 규칙을 정했습니다! 
> **"앞으로 다른 부서에 요청을 넣을 때는 반드시 내가 만들어둔 공식 A4 결재 서류 양식에 맞게 빈칸을 채워서, 지정된 내선 전화번호로만 연락해라!"**
>
> 이 **'공식 결재 서류 양식(데이터 객체)'**과 **'부서 간 전용 내선 전화번호부(인터페이스)'**를 딱 하나로 모아둔 공용 책자가 바로 `contracts` 모듈입니다!

---

## 🚀 비즈니스 목적과 MSA에서의 중요성

* **오타와 실수 원천 차단 (타입 안전성):** 
  마이크로서비스(MSA)들끼리 통신할 때 문자열(JSON)로만 대화하면 오타가 나기 쉽습니다. 각 모듈은 이 `contracts` 책자를 가져다가 쓰면, Java 코드가 자동으로 규격을 잡아줘서 오타 없이 안전하게 데이터를 주고받을 수 있습니다.
* **부서 간 독립성 확보 (느슨한 결합):** 
  `loan` 개발자는 `journal-ledger`의 복잡한 수학 공식 코드를 전혀 몰라도 됩니다. 그냥 이 `contracts` 모듈에 정의되어 있는 껍데기 양식(DTO) 하나만 보고 빈칸을 채워서 딸깍 던지기만 하면 끝납니다.

## 📦 이 모듈 안에 들어가는 것들

1. **DTO (Data Transfer Object):** API 통신을 주고받을 때 사용하는 "요청/응답" 데이터 박스 형틀.
2. **Event Schema:** "나 대출 승인냈어!" 하고 시스템 동네방네 확성기로 떠들 때(카프카) 쓰는 메세지의 규격 (예: `LoanApprovedEvent`).
3. **Port (인터페이스):** 저쪽 부서에 연락할 수 있는 껍데기 메서드 명세서.
