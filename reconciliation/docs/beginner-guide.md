# Reconciliation Beginner Guide

## 1. 대사가 무엇인가요

대사는 "두 데이터가 서로 맞는지 확인하는 일"입니다.

예시:
- 은행 입출금 내역과 회계장부가 맞는지 확인
- 보조원장과 총계정원장이 맞는지 확인
- 원천 시스템 금액과 전표 금액이 맞는지 확인

이 모듈은 이런 비교를 자동화하고, 차이가 나면 그 차이를 추적하도록 돕습니다.

## 2. 초보자가 먼저 알아야 할 용어

- 대사 단위: 무엇과 무엇을 비교할지 정한 묶음
- 대사 규칙: 어떤 조건으로 같다고 볼지 정한 기준
- 대사 실행: 실제로 비교를 돌린 결과
- 차이: 비교 결과 맞지 않는 항목
- 사유코드: 왜 차이가 났는지 분류하는 코드
- 조정분개: 차이를 회계적으로 보정하기 위한 분개
- SLA: 언제까지 처리해야 하는지 정한 기한

## 3. 실무 흐름을 쉬운 말로 보면

1. "어떤 비교를 할지" 대사 단위를 만듭니다.
2. "어떻게 같다고 볼지" 규칙을 만듭니다.
3. 대사를 실행합니다.
4. 맞지 않으면 차이를 생성합니다.
5. 담당자를 배정합니다.
6. 사유를 정하고 필요하면 조정분개를 연결합니다.
7. 해결되면 `RESOLVED`, 의미 없는 차이면 `IGNORED`로 마감합니다.

## 4. 현재 코드에서 꼭 알아야 할 현실

현재 구현은 완성형 대사 엔진이라기보다 뼈대와 운영 규칙을 먼저 세운 상태에 가깝습니다.

- 메인 대사 실행은 더미 금액 대신 `criteriaJson`의 원천 집계값과 전표 조회 포트의 대상 집계값을 비교합니다.
- 대사 규칙에 금액 허용오차를 두면, 집계 금액 차이가 허용 범위 안일 때는 차이를 만들지 않습니다.
- 자동 조정분개가 필요한 대사라면 `criteriaJson`에 `adjustmentDebitAccountCode`, `adjustmentCreditAccountCode`를 넣어야 합니다.
- 조정분개 자체는 대사 서비스가 직접 저장하지 않고 전표 생성 포트로 요청합니다.
- 심화 대사 흐름은 `matchingRulesJson`의 SOURCE/INTERFACE 집계값과 전표/원장 조회 포트를 함께 사용합니다.
- 다만 SOURCE/INTERFACE는 아직 외부 원천 시스템 직접 조회가 아니라 설정에 명시된 집계값입니다.
- 자동 매칭도 아직 단순합니다.
- 하지만 차이 생성, 사유코드, 담당자, SLA, 조정분개 연결 구조는 이미 들어 있습니다.

## 5. 자동 매칭은 지금 어떻게 동작하나요

현재 `AutomatedMatchingEngine`는 금액과 일자를 중심으로 봅니다.

- 기본 호출에서는 금액이 같아야 함
- 기본 호출에서는 거래일자와 회계일자가 정확히 같아야 함
- `MatchOptions`를 넘기면 금액 차이와 일자 차이를 허용 범위 안에서 매칭할 수 있음
- 전표 상세 입력은 `JournalDetailSummary` 계약 DTO를 사용함

즉:
- 기본 호출에서는 날짜가 하루만 달라도 실패
- 옵션 호출에서는 예를 들어 "1일 이내, 1.00원 이내" 같은 기준을 줄 수 있음
- 설명이 비슷해도 금액이나 날짜가 다르면 실패

초보자는 이 점 때문에 실제 운영에서는 매칭 실패가 꽤 많이 나올 수 있다는 걸 먼저 이해하면 됩니다.

## 6. 차이가 났을 때 왜 사유코드가 중요한가요

모든 차이가 오류는 아닙니다.

예:
- 시간차이
- 수수료 차이
- 수기 입력 오류
- 아직 반영되지 않은 거래

그래서 차이는 "왜 났는지"를 코드로 남겨야 나중에 분석과 반복개선이 가능합니다.

또한 어떤 사유는 조정분개가 꼭 필요합니다. 이 모듈은 그 규칙도 같이 관리합니다.

## 7. 처음 호출해보기 좋은 API 순서

1. `POST /api/reconciliation/units`
2. `POST /api/reconciliation/rules`
3. `POST /api/reconciliation/reason-codes`
4. `POST /api/reconciliation/run`
5. `GET /api/reconciliation/runs/{runId}/differences`
6. `POST /api/reconciliation/differences/assign`
7. `POST /api/reconciliation/differences/resolve`

## 8. 헷갈리기 쉬운 부분

### 왜 모델이 두 종류인가요?

현재 코드에는:
- 일반 대사 API용 모델
- SOURCE -> INTERFACE -> JOURNAL -> LEDGER 심화 대사용 모델

이 같이 들어 있습니다.

초보자는 먼저 `ReconciliationUnit` 계열을 메인으로 이해하면 됩니다.
