## Problem statement

The direct core reaggregation query has no ORDER BY and the service preserves encounter order using LinkedHashMap. Carry-forward requires earlier days to have been saved first.

## Reproduction / evidence

P08 feeds day2 debit20 before day1 debit100 into the actual bulk service; day2 ends at20 instead of120. The batch reader is already ordered correctly. This finding concerns the public core service, currently described in docs but not found in an active module caller.

Executed diagnostic observations: `P08` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

A caller of the documented core rebuild can regenerate wrong opening/ending balances from correct source journals.

## Proposed solution

Process date groups chronologically independent of repository ordering, and specify ordering on the source query where useful.
