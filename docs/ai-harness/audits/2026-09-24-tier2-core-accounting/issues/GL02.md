## Problem statement

Event enrichment uses putIfAbsent for createdBy/auditUser, preserving caller-supplied names. The posting-contract route also copies body creator/audit fields without binding them to an authenticated caller.

## Reproduction / evidence

Static reproduction: authenticated Alice submits eventData.auditUser="Bob"; JournalRuleEngine prioritizes that field and sets both creator and audit actor to Bob. Gateway identity sanitation applies to headers, not these JSON fields.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

Financial lineage can falsely attribute journal creation to another user and undermine maker-checker controls.

## Proposed solution

Reserve actor fields for verified inbound context. For delegated service submissions, authenticate the service and record both service principal and validated initiating actor.

## Acceptance criteria

- [ ] Forged, blank and conflicting body actors cannot override the trusted caller.
- [ ] Exercise both event and posting-contract endpoints through the web boundary.
- [ ] Keep original source actor separately if needed; do not treat it as an approval identity.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.
