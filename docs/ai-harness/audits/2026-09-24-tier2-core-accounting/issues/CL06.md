## Problem statement

The supplied retained-earnings account is checked only for nonblank text. Journal account validation verifies historical existence, not whether it is an approved equity destination.

## Reproduction / evidence

P17 supplies CASH_ASSET and the generated annual command credits it1000. Actual persistence would also require that account to exist; no database posting was performed by the probe.

Executed diagnostic observations: `P17` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

A balanced annual transfer can move profit into cash, revenue or expense instead of retained earnings, corrupting the balance sheet and P&L closure.

## Proposed solution

Resolve an approved entity/year retained-earnings mapping and validate its dated equity/postability classification.

## Acceptance criteria

- [ ] Reject asset, liability, revenue, expense and unknown destinations before creating a draft.
- [ ] Prove approved retained-earnings configuration for profit, loss and zero-net-income years.
- [ ] Audit explicit configuration changes rather than letting arbitrary request text select the destination.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.

## Test gap and verification limits

Annual service tests verify sign and totals but not destination account classification.
