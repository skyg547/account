## Problem statement

The default JPA adapter loads all GL and SL balances for the requested range and passes those entities into deleteAllInBatch. The paged chunk100 reader does not bound this preparatory phase.

## Reproduction / evidence

Static evidence is the findByBalanceDateBetween → deleteAllInBatch(entities) call chain. Memory/cardinality and generated delete predicates grow with the entire range. No heap/load measurement was performed; JDBC cleanup already uses predicate DELETE.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

Large rebuilds can fail or stall before bounded processing begins, leaving the operational recovery path unsuitable for scale.

## Proposed solution

Delete by date predicate behind the output port without materializing entities, and coordinate with the publication protocol in GL13.
