## Problem statement

Any supplied approver can approve a DRAFT directly. The domain does not compare approver with createdBy, require a submitted/requested state, or validate the approver identity. The HTTP approval/posting commands do not consume the trusted role context.

## Reproduction / evidence

P02 creates a journal as maker and calls approve("maker"); status becomes APPROVED. Static controller/service tracing finds no authorization policy. Gateway reconstructs trusted identity headers, so this is not a claim of header spoofing through Gateway.

Executed diagnostic observations: `P02` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

One authenticated user can create and approve financial entries without independent review; users without accounting approval permissions can reach approval commands.

## Proposed solution

Introduce command-level permission checks and durable distinct maker/approver identities, with an explicit policy for machine-generated adjustments and a controlled submission transition.

## Acceptance criteria

- [ ] Reject self-approval using canonical trusted identities, including event and machine paths.
- [ ] Deny missing or insufficient roles; test viewer, maker, approver and posting permissions through HTTP.
- [ ] Require the intended submission state or explicitly approve a documented equivalent workflow; preserve separate approval evidence after posting.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.

## Test gap and verification limits

Existing transition tests prove state predicates and balance checks, but do not test self-approval or actual HTTP role enforcement.

The six requested module suites passed 369 tests, but their success does not establish this missing control. No production data, live PostgreSQL, distributed fault injection or production load testing was used for this audit. A remediation must supply the relevant additional evidence before this issue is closed.
