## Problem statement

Reopening changes calendar status but does not invalidate or version the prior completed tasks/passed gates. No close-cycle ID or source watermark ties evidence to the current financial state.

## Reproduction / evidence

P16 executes close → reopen → start → readiness check → close with the same task and gate objects; all transitions succeed.

Executed diagnostic observations: `P16` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

Adjustments made after reopening can be reclosed without a renewed reconciliation or approval cycle.

## Proposed solution

Preserve prior evidence and open a new versioned close cycle requiring evidence relevant to the new source snapshot.

## Acceptance criteria

- [ ] Prior evidence remains immutable and traceable but cannot satisfy a changed cycle automatically.
- [ ] New post-reopen activity forces required controls to be rerun.
- [ ] Tests cover unchanged and changed reopen scenarios and explicit evidence carry-over rules if allowed.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.
