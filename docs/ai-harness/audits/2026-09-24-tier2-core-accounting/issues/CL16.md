## Problem statement

The source selects every account on foreign-currency journal lines. The service loads account metadata but does not apply monetary-item eligibility or historical-cost valuation policy; only the code is used.

## Reproduction / evidence

P13 generates a200 adjustment for an account marked fixedAsset=true. Static example: cash Dr100/revenue Cr100 in foreign currency, base110 each, rate1.2. Valuing both generates cash gain10 and revenue loss10, cancelling net FX gain while restating historical revenue. Fixed-asset classification alone is not a complete accounting policy; the missing explicit eligibility policy is the defect.

Executed diagnostic observations: `P13` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

Historical revenue/expense and nonmonetary asset values can be improperly remeasured and genuine FX gains/losses offset.

## Proposed solution

Define dated monetary-account/valuation eligibility and fail closed when classification is insufficient; filter and validate both source and service input.

## Acceptance criteria

- [ ] Cash and monetary liabilities are included with correct normal/abnormal signs.
- [ ] Historical revenue/expense and historical-cost nonmonetary assets are excluded; supported exceptions use explicit policy.
- [ ] Test complete two-sided foreign journals, not isolated eligible account balances only.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.
