## Problem statement

Untyped decimal JSON becomes a Double under the default Jackson mapper. Rule interpolation stringifies the rounded floating-point value before its BigDecimal parser and ledger precision checks execute.

## Reproduction / evidence

P06 deserializes 900719925474099.11 through ObjectMapper Map handling; the value becomes 900719925474099.10 and passes AccountingPrecision. No production decimal-preserving mapper setting was found in the inspected Journal/shared Java path. The probe is a default-mapper reproduction, not an MVC launch.

Executed diagnostic observations: `P06` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

Identical cent loss on debit and credit yields a balanced but financially incorrect journal. Excess-precision input may also become an apparently valid exact amount.

## Proposed solution

Use typed BigDecimal event contracts or verify decimal-preserving untyped deserialization at every HTTP/message boundary.

## Acceptance criteria

- [ ] An actual MVC event request preserves 900719925474099.11 exactly.
- [ ] Reject 100.000000000000001 before it can round to100.00.
