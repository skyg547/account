## Problem statement

The detail adapter leaves category null when dated account lookup is absent. Annual close then filters for REVENUE/EXPENSES and silently discards unclassified lines rather than failing completeness validation.

## Reproduction / evidence

Static reproduction: provide a posted revenue detail whose historical master category is missing; the service omits it, possibly creates a partial balanced transfer, or returns with no journal. This requires incomplete/corrupt historical reference data and is not inevitable on a valid dataset.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

Retained earnings and temporary-account clearing can be incomplete while the close command succeeds.

## Proposed solution

Fail closed for unknown or missing classification on posted source lines and reconcile classified source counts/totals before transfer.

## Acceptance criteria

- [ ] Missing history, null category and unsupported category values produce a completeness error.
- [ ] Legitimate non-P&L accounts are explicitly classified and excluded without error.
