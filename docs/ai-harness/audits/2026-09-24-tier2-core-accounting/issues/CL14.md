## Problem statement

Financial domain classes are JPA entities with persistence callbacks and relationships. Port isolation at application boundaries does not satisfy the requested pure domain contract.

## Reproduction / evidence

Static imports/mappings show framework dependence in calendar, task, gate, lock, approval, batch and daily status models. This finding is separately owned from GL19 but should share an architecture migration policy.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

Persistence lifecycle and domain rules remain coupled; framework changes can affect financial state behavior and tests.

## Proposed solution

Move persistence representations into infrastructure incrementally and map them to explicit domain aggregates.
