## Problem statement

Bulk keys substitute literal NULL for absent dimensions and join strings with '|'; query aggregation separately maps null to empty. These encodings are not injective.

## Reproduction / evidence

P10 posts debit10 for partner null and debit20 for partner "NULL" on the same date/account; one SL row30 is saved. No domain reservation of that literal was found. Delimiter-containing components create additional collisions.

Executed diagnostic observations: `P10` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

Totals remain balanced at GL level while counterparty/department attribution is silently corrupted.

## Proposed solution

Use typed key records directly for both write and query maps, preserving absent, empty and literal values distinctly or validating an explicit canonical policy.

## Acceptance criteria

- [ ] Cover null, literal NULL, empty and delimiter-containing dimension components.
- [ ] Write and query aggregation use the same documented equivalence rules.
- [ ] Verify distinct SL rows and total reconciliation in persistence tests.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.
