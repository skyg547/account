## Problem statement

GL/SL update reads absolute totals, adds amounts in Java and saves absolute totals. Neither balances nor reads have version/exclusive locking. PostgreSQL upsert overwrites with EXCLUDED totals rather than adding an atomic delta.

## Reproduction / evidence

Static schedule: initial balance100, two journals add10/add20 after both read100, then save110/save120. Both entry inserts can commit with final balance120 rather than130. PostgreSQL execution was not performed.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

Ledger balances can omit valid posted movements; balanced journals do not protect account-level reporting.

## Proposed solution

Use atomic increments or serialize balance keys with conflict retries, including safe row creation and a consistent lock order across accounts.
