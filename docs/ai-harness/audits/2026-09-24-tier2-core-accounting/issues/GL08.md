## Problem statement

Balance equality is enforced independently in each unit, but no invariant verifies baseAmount against transaction currency, exchange rate and rounding policy. The automatic rule engine assigns baseAmount=amount for every currency and does not apply an event FX rate; the contract adapter also defaults missing base to amount.

## Reproduction / evidence

P05 approves and creates a posting snapshot for USD100/rate1300 with base100 on both lines. The two currencies balance independently while functional value is wrong. Rule-engine source confirms the same unit assumption on automated input.

Executed diagnostic observations: `P05` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

Foreign-currency journals can be understated/overstated by the exchange rate while passing all debit/credit checks.

## Proposed solution

Define currency/rate provenance and per-line conversion policy, require real conversion for foreign inputs, and explicitly handle rounding residuals rather than silently assuming one-to-one units.

## Acceptance criteria

- [ ] USD100 at1300 requires base130000 or an explicit supported exception with evidence.
- [ ] Reject missing/inconsistent FX data and apply the same rules to manual, contract and rule-based creation.
- [ ] Test multiple lines whose rounded conversions need a controlled residual adjustment; preserve exact base debit/credit equality.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.

## Test gap and verification limits

Precision tests check decimal scale and balance equality, but not semantic currency conversion.

The six requested module suites passed 369 tests, but their success does not establish this missing control. A remediation must supply the relevant additional evidence before this issue is closed.
