## Problem statement

GL balances store baseAmount under a transaction-currency key. The allowance lookup returns that functional balance, but ECL subtracts it directly from the currency-specific target, duplicates the result into amount/baseAmount, and the journal adapter supplies exchange rate one.

## Reproduction / evidence

P14 supplies USD target100 and existing base credit104000 (USD80 at1300). Actual service generates allowance DEBIT103900, a release, instead of USD20 additional provision/base26000. With no existing allowance, a USD100 target is posted with base100. This is a synthetic service-port reproduction; the unit flow is additionally traced through actual adapters.

Executed diagnostic observations: `P14` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

Foreign allowance and impairment expense can be mismeasured by orders of magnitude and in the wrong direction.

## Proposed solution

Make monetary units explicit in source/balance ports and convert consistently using a dated exchange-rate policy or maintain true dual-currency balances.

## Acceptance criteria

- [ ] Foreign additions/releases/equality use comparable units and correct base amounts/rate.
- [ ] Test changed FX rate, missing rate and non-reporting currencies with real adapter contracts.
- [ ] Reconcile resulting posted allowance to confirmed target in both transaction and functional units.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.

## Test gap and verification limits

Current ECL tests use numerically compatible same-currency targets/balances.
