## Problem statement

The automatic number uses only four hexadecimal UUID characters. Unique slip storage detects a collision, but creation has no retry/sequence allocator. The daily key space is only 65536.

## Reproduction / evidence

P11 executed 5000 same-day create calls through the real numbering service and observed 197 duplicate numbers using a capturing persistence double. Counts are random and vary per run. A real unique constraint turns such collisions into failed creates rather than silently overwriting a row.

Executed diagnostic observations: `P11` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

Ordinary daily enterprise volume experiences avoidable journal creation failures; a later retry without durable event identity can worsen ambiguity.

## Proposed solution

Use a concurrency-safe database sequence or sufficiently large unique allocation strategy within the 20-character contract, coordinated with idempotency.
