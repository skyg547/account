## Problem statement

Summary stage amounts are loaded and individually checked for nonnegativity, but their sum is never compared with the target. The provision service consumes only the target amount.

## Reproduction / evidence

P15 accepts target100 with stages1+2+3=6. Upstream summary generation filters COMPLETED calculation results, so absence of finalized-result filtering is not the finding; the closing boundary still accepts inconsistent totals.

Executed diagnostic observations: `P15` in [probe-results.json](../evidence/probe-results.json); source: [AuditProbes.java](../evidence/AuditProbes.java). Probe PASS confirms the observation, not remediation.

## Financial / architectural impact

A corrupt, stale or mismapped ECL summary can produce a balanced but unreconciled provision.

## Proposed solution

Require stage-total reconciliation before group rounding/posting and preserve the verified source totals as evidence.

## Acceptance criteria

- [ ] Inconsistent stage totals fail before any adjustment is created.
- [ ] Cover direct-port and grouped JDBC input, including high-precision amounts and zero portfolio policy.
- [ ] Round once at the documented posting boundary after exact source reconciliation.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.
