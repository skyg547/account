## Problem statement

The service checks single run/model input but discards those identifiers when grouping and creating journal lineage. The resulting reference contains caller batch ID, allowance account and currency. Upstream same-date summaries can be deleted and rebuilt.

## Reproduction / evidence

Static reproduction: create from RUN-A/MODEL-A, rebuild the same date as RUN-B/MODEL-B with the same amount and reuse batch ID. Financial command content remains identical and does not retain the original model snapshot identity.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

An adjustment cannot reliably prove which confirmed ECL calculation/model justified it after source regeneration.

## Proposed solution

Persist an immutable snapshot reference containing run/model/date/entity identity and reconciliation evidence; keep it separate from transient execution IDs.

## Acceptance criteria

- [ ] Posted and draft adjustments retain resolvable original ECL snapshot identity after source rebuild.
- [ ] Replay with a different snapshot under the same operation key is rejected or explicitly versioned.
- [ ] Do not rely on reconstructing run identity from a mutable same-date summary table.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.
