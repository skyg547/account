## Problem statement

The remote-source journal pool is fixed at one connection with a five-second acquisition timeout, while FX supports multiple concurrent cursor partitions. Each open cursor holds a connection.

## Reproduction / evidence

Conditional static reproduction: configure gridSize>1 and run at least two populated ranges; if the first cursor takes over five seconds, other workers can time out acquiring their reader connection. Default grid size one avoids this particular conflict; no production load run was performed.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

Documented/configurable parallel execution can fail from internal resource sizing rather than source data quality.

## Proposed solution

Size the source pool to approved cursor concurrency or validate/clamp concurrency against the pool; retain a bounded resource budget.

## Acceptance criteria

- [ ] A multi-partition test holds one cursor beyond five seconds and demonstrates supported workers complete without pool starvation.
