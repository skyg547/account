## Problem statement

Reopen approval and its calendar are read without a lock/version. Approval and rejection branches can both act on a stale PENDING snapshot and overwrite the final decision.

## Reproduction / evidence

Static schedule: A/B load PENDING; A approves and opens the master period; B rejects and commits the last approval-row update. Result can be OPEN with REJECTED approval. Master fiscal status writes have a pessimistic row lock, but that does not serialize the preceding local decision or the rejection branch.

Evidence level: source and call-path analysis. The described failure schedule is a reproduction plan unless explicitly identified as executed above.

## Financial / architectural impact

Authoritative approval evidence can disagree with actual posting permissions.

## Proposed solution

Serialize or version the local decision/calendar aggregate before validating, and couple its durable decision to the remote operation protocol.

## Acceptance criteria

- [ ] Barrier-controlled approve-versus-reject permits exactly one decision; loser receives conflict.
- [ ] Final calendar/master admission state agrees with the winning decision after failure recovery.
- [ ] Exercise concurrent close/start/task/gate changes under the same aggregate consistency policy.
- [ ] Add regression coverage that fails on the audited version and passes after remediation; preserve existing financial controls.
