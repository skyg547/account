# 코드·문서 품질 계약

구현자는 변경과 함께 아래 Q1–Q4의 근거를 반환하고, 별도 독립 리뷰어는 실제 diff·테스트·설명을 대조한다.
초보자 설명: 코드가 동작하는지뿐 아니라 다음 사람이 이름과 설명을 보고 안전하게 고칠 수 있는지도 확인하는 계약이다.

## 적용 범위

승인된 변경과 직접 영향을 받는 설명에만 적용한다. 기존 코드 전수 리팩터링은 금지하고,
일괄 주석 추가는 금지하며, 범위 밖 문서 정리도 금지한다. 필요한 파일이 allowlist 밖이면 부모에게 범위 결정을 요청한다.
문서 전용 변경은 해당하지 않는 코드 항목에 N/A를 사용할 수 있지만 검토 자체를 생략하지 않는다.
기존 역할·권한과 Ready·merge 승인 게이트는 변경하지 않는다. 리뷰어는 읽기 전용이며 공유 기록과 Git/GitHub 변경은 승인된 부모 소유다.

## Q1. 읽기 쉬운 코드와 책임

- 목적과 단위를 드러내는 명확한 이름, 응집된 작은 함수, 단일 책임을 유지한다. 함수 줄 수 자체를 목표로 쪼개지 않는다.
- 같은 규칙의 중복을 최소화하되 불필요한 추상화나 한 번 쓰는 전달 계층을 만들지 않는다.
- 기존 MSA·헥사고날·DDD 경계, 성능, 금융 정합성을 우선한다. 간결함을 위해 BigDecimal 정밀도, bulk 처리, 멱등성 검증을 없애지 않는다.
- 근거는 변경된 함수·클래스 위치와 관련 테스트다. 이름이 짧다는 사실만으로 PASS가 되지 않는다.

## Q2. 핵심 흐름과 설계 이유

승인된 변경의 핵심 로직에 입력→처리→출력, 설계 이유, 예외·경계와 해당 시 재실행 동작을 설명한다.
적절한 코드 주석 또는 기능 문서에 두고 서로 연결한다. 동일 장문 중복을 강요하지 않는다.
Q4의 가까운 의도 주석은 긴 흐름 설명을 복사하는 대신 필요한 이유와 문서 위치만 짧게 안내할 수 있다.

이 변경의 예: 로컬 테스트는 네 문서를 입력받아 세 진입점의 필수 연결과 품질 절·완료표 구조를 검사하고,
누락/잘못된 링크를 assertion 실패로 출력한다. 임의 링크를 따라가지 않는 이유는 승인된 입력 밖을 읽지 않기 위해서다.
새 42번 문서가 없으면 빈 입력으로 처리해 계약 실패를 보여주고, 그 외 읽기 오류는 숨기지 않는다.
동일 입력으로 재실행해도 파일이나 외부 상태를 쓰지 않는다. 자세한 근거는 `tools/ci/harness-quality-contract.test.cjs`다.

## Q3. 기능 문서와 초보자 안내

- 검증된 코드와 명령을 기준으로 대상 모듈 README/기능 문서를 최신화한다. 변경된 동작·파라미터·실행법·제약과 맞지 않는 설명을 고친다.
- 초보자가 따라갈 수 있도록 전제 조건, 실행 예, 기대 결과, 제약을 적는다. 미검증 명령을 실행 성공한 것처럼 쓰지 않는다.
- WORKLOG는 기능 문서를 대체하지 않는다. 작업 이력은 부모의 공유 기록에, 사용법과 동작 설명은 모듈 기능 문서에 둔다.
- 문서 변경이 필요 없다는 판단도 영향 파일과 사유를 남겨 독립 리뷰를 받는다. 허용 범위 밖 문서를 몰래 수정하지 않는다.

## Q4. 비자명 로직의 의도 주석

변경된 비자명한 로직 가까이에 의도와 설계 이유를 짧게 적는다. 예를 들어 링크를 따라 파일을 읽지 않는 검사는
단순한 경로 비교처럼 보여도 읽기 범위를 지키려는 목적이 있으므로 테스트 코드 옆에서 이유를 설명한다.
유익한 주석은 보존하고, 변경 후 사실과 어긋난 오래된 주석은 수정한다. 자명한 매줄 주석은 강요하지 않는다.
주석은 코드가 하는 일을 그대로 번역하기보다 왜 필요한지를 설명하며 실제 구현과 일치해야 한다.
문서 전용 변경이라 비자명 코드가 바뀌지 않았다면 이 항목은 구체적 사유와 함께 N/A 가능하다.

## 판정과 증거

- PASS: 해당 항목을 확인했고 현재 파일·테스트 근거가 있다. 테스트 성공만으로 설명의 정확성까지 PASS로 판단하지 않는다.
- FAIL: 기준 미충족 또는 필요한 검증/근거가 없다. FAIL이나 근거 누락이 남으면 완료로 처리하지 않는다.
- N/A: 해당 항목이 변경에 적용되지 않는 구체적 사유와 영향 근거를 적고 독립 리뷰어가 확인한다. 단순히 귀찮거나 실행 환경이 없다는 이유는 N/A가 아니다.
- 테스트 미실행은 PASS가 아니다. 명령·미실행 사유·위험·다음 검증 게이트를 남긴다. 필요한 테스트가 미실행이면 관련 항목은 미검증 FAIL로 보류하며 코드 결함으로 단정하지 않는다.
- 독립 리뷰어는 결과와 N/A 사유를 대조하고 수정이 필요하면 원래 작성자에게 반환한다. 직접 수정하거나 승인 권한을 확대하지 않는다.

## 완료표 템플릿

아래 표를 완료 보고/PR 본문 초안에 복사하고 `선택`, `작성`, `확인 대기`를 실제 값으로 바꾼다.
판정은 PASS/FAIL/N/A 중 하나만 선택한다. 해당 없는 사유·위험 칸도 빈칸 대신 `해당 없음: 이유`를 적는다.
파일은 경로:라인, 테스트는 실행 명령·결과를 적고, 독립 리뷰 확인에는 검토자와 근거 또는 미해결 사항을 남긴다.
Q1=코드 품질, Q2=흐름 설명, Q3=기능 문서, Q4=의도 주석이다.

| 항목 | 판정 (PASS/FAIL/N/A) | 파일·테스트 근거 | N/A 사유 | 위험·다음 검증 게이트 | 독립 리뷰 확인 |
| --- | --- | --- | --- | --- | --- |
| Q1 | 선택 | 작성 | 작성 | 작성 | 확인 대기 |
| Q2 | 선택 | 작성 | 작성 | 작성 | 확인 대기 |
| Q3 | 선택 | 작성 | 작성 | 작성 | 확인 대기 |
| Q4 | 선택 | 작성 | 작성 | 작성 | 확인 대기 |

예: 문서 오탈자만 바꿨다면 Q4는 `N/A`, 근거는 `수정한 문서 경로:라인; 코드 diff 없음`,
사유는 `비자명 코드 변경 없음`으로 적는다. 독립 리뷰어가 실제 diff를 확인하기 전에는 확인 완료로 표시하지 않는다.

## 로컬 검사와 한계

전제: Node.js의 내장 `node:test`를 실행할 수 있는 환경과 저장소 루트 작업 디렉터리. 패키지 설치나 네트워크 접근은 필요 없다.

```powershell
node --test tools/ci/harness-quality-contract.test.cjs
git diff --check
```

기대 결과: 모든 Node 테스트 통과, 실패 0 및 종료 코드 0. `git diff --check`는 공백 오류가 없을 때 종료 코드 0이다.
문서 링크/필수 절/증거표를 제거하거나 잘못된 대상으로 바꾼 인메모리 입력이 거부되는지도 검사한다.
이 테스트는 CI 미연결이며 연결 작업은 #672에서 별도 추적한다. 기존 CI 성공을 이 검사 실행 증거로 삼지 않는다.
문서 구조 검사는 실제 코드 품질과 설명의 사실성에 대한 의미 검증을 대체하지 않는다. 적절한 이름·책임·설명·예외 판단은 독립 리뷰가 필요하다.
