# 🍃 [Tech 03] Spring Boot 3.4

### 👶 초보자를 위한 개념 설명
> **Spring Boot란 무엇인가요?**
> 마치 **"요리 조리법과 도구가 다 준비된 밀키트(Meal Kit)"**와 같습니다. 원래 서버를 만드려면 가스레인지도 사고 칼도 사고 재료도 씻어야 하지만(Spring Framework), Spring Boot는 포장을 뜯고 불만 켜면 요리가 완성되도록 모든 설정을 자동으로 해줍니다.

### 💡 주요 특징 및 예시
1. **Auto Configuration**: 우리가 "나는 데이터베이스를 쓸 거야"라고 말만 하면 배경 설정을 알아서 다 해줍니다.
2. **Embedded Server (Tomcat)**: 따로 서버를 설치할 필요 없이 실행 버튼만 누르면 서버가 돌아갑니다.
3. **Observability**: 우리 서버가 지금 얼마나 아픈지, 건강한지(CPU, 메모리 등) 실시간으로 모니터링할 수 있는 도구를 제공합니다.

### 🛠️ 우리 프로젝트에서의 활용
- **Microservices**: `journal-ledger`, `master-data` 등 개별 독립 서비스를 빠르게 기동하는 엔진으로 사용됩니다.
- **REST API**: 프론트엔드가 데이터를 가져갈 수 있도록 창구를 만드는 데 사용됩니다.

### 🚀 실전 사용 가이드 (Step-by-Step)
**[간단한 데이터 조회 API 만들기]**
1. **Controller 작성**: 사용자가 접속할 '입구' 주소를 만듭니다.
   ```java
   @GetMapping("/api/hello")
   public String hello() { return "Welcome!"; }
   ```
2. **DTO 정의**: 주고받을 데이터 규격을 만듭니다.
3. **Service 연동**: 버튼을 눌렀을 때 실행될 비즈니스 로직을 연결합니다.
4. **확인**: 서버 재시작 후 브라우저에서 해당 주소로 접속해 응답이 오는지 확인합니다.

# 📐 [Tech 04] Hexagonal Architecture (Port & Adapter)

### 👶 초보자를 위한 개념 설명
> **육각형 아키텍처(Hexagonal)가 무엇인가요?**
> 마치 **"만능 어댑터나 USB 포트"**와 같습니다. 핵심 알맹이(비즈니스 로직)는 바꾸지 않고, 꽂는 장비(DB, 웹 UI, 모바일 앱 등)만 자유자재로 갈아 끼울 수 있게 설계하는 방식입니다.

### 💡 주요 구조 및 예시
1. **Core (알맹이)**: "은행 전표는 100원 이상이어야 해" 같은 가장 중요한 규칙들을 담은 곳입니다.
2. **Port (구멍)**: "데이터를 저장하고 싶어", "누가 돈을 보내달래" 같은 소통 통로(인터페이스)입니다.
3. **Adapter (플러그)**: 실제로 DB에 저장하거나, 웹 브라우저에 보여주는 실제 도구입니다.

### 🛠️ 우리 프로젝트에서의 활용
- **코드 수명 보장**: 나중에 데이터베이스를 MySQL에서 Oracle로 바꿔도, 핵심 비즈니스 로직(Core)은 한 줄도 고칠 필요가 없게 설계되었습니다. 
- **AGENTS.md 준수**: 우리 팀의 작업 규칙 중 하나인 "Hexagonal Architecture 원칙 엄격 준수"가 바로 이것입니다.

### 🚀 실전 사용 가이드 (Step-by-Step)
**[새로운 비즈니스 로직 추가하기]**
1. **Domain 작성**: `domain` 패키지에 핵심 규칙과 데이터를 담은 클래스를 만듭니다.
2. **Port(인터페이스) 정의**: `application.port.out`에 "나는 이런 서비스가 필요해"라고 인터페이스를 정의합니다.
3. **Service 구현**: `application.service`에서 Domain과 Port를 조립하여 유즈케이스를 완성합니다.
4. **Adapter(구현체) 구현**: `infrastructure.adapter`에서 실제로 DB에 저장하는 구체적인 코드(JPA 등)를 작성합니다.
