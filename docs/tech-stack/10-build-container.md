# 🐘 [Tech 24] Gradle

### 👶 초보자를 위한 개념 설명
> **Gradle이란 무엇인가요?**
> 마치 **"레고 조립 설명서 및 부품 조달 팀"**과 같습니다. "여기는 빨간 블록이 필요해"라고 적어두면 전 세계의 상점(Maven Central)을 돌아다니며 부품을 사오고, 조립 순서에 맞게 전체 시스템을 빌드해줍니다.

### 💡 주요 특징 및 예시
1. **Dependency Management**: `implementation '...'` 한 줄로 수천 줄의 외부 코드를 가져오게 해줍니다.
2. **Multi-module Build**: 우리 프로젝트처럼 수많은 서비스가 쪼개져 있어도 효율적으로 한 번에 조립할 수 있습니다.

### 🚀 실전 사용 가이드 (Step-by-Step)
**[새 부품(라이브러리) 추가하기]**
1. **파일 열기**: `build.gradle` 파일을 엽니다.
2. **코드 추가**: `dependencies { implementation '라이브러리이름' }`을 추가합니다.
3. **새로고침**: IDE에서 Gradle 메뉴의 새로고침(또는 빌드) 버튼을 누르면 부품이 자동으로 다운로드됩니다.

# 🐳 [Tech 25] Docker

### 👶 초보자를 위한 개념 설명
> **Docker란 무엇인가요?**
> 마치 **"컨테이너 규격"**과 같습니다. 예전에는 과일(앱)을 배에 실을 때 모양이 제각각이라 힘들었지만, 똑같은 크기의 컨테이너(Docker)에 담으면 내 컴퓨터든 사장님 컴퓨터든 서버실이든 똑같이 완벽하게 작동합니다.

### 💡 주요 특징 및 예시
1. **Isolation**: 내 컴퓨터의 설정이 꼬여있어도 컨테이너 안의 깨끗한 환경에서 앱이 돌아갑니다.
2. **Portability**: "내 컴퓨터에선 됐는데 사장님 컴퓨터에선 안 되네요"라는 유구한 문제를 해결해줍니다.

### 🚀 실전 사용 가이드 (Step-by-Step)
**[컨테이너로 앱 실행하기]**
1. **Dockerfile 작성**: 앱이 실행될 깨끗한 방의 환경(OS, 실행 명령어 등)을 적습니다.
2. **이미지 빌드**: `docker build -t my-app .` 명령으로 컨테이너 설계도를 만듭니다.
3. **컨테이너 실행**: `docker run my-app` 명령으로 방을 만들어 앱을 기동시킵니다.

# 🚨 [Tech 26] ESLint

### 👶 초보자를 위한 개념 설명
> **ESLint란 무엇인가요?**
> 마치 **"똑똑한 맞춤법 검사기"**와 같습니다. 코딩을 하다가 "여기는 세미콜론이 빠졌어요!", "이 변수는 안 쓰고 있어요!"라고 실시간으로 알려주어 코드가 지저분해지는 것을 막아주는 청소 반장입니다.

### 💡 주요 특징 및 예시
1. **Rule Enforcement**: 우리 팀의 코딩 스타일(예: 따옴표는 무조건 ' '만 쓰기)을 강제합니다.
2. **Auto Fix**: 명령어 하나로 엉망인 코드 줄 바꿈을 한 번에 예쁘게 정리해줍니다.

### 🚀 실전 사용 가이드 (Step-by-Step)
**[코드 스타일 자동 정리하기]**
1. **작성**: 코드를 자유롭게 칩니다. (오타나 스타일 오류가 나면 빨간 밑줄이 뜹니다.)
2. **명령 실행**: 터미널에서 `npm run lint` 또는 `eslint --fix`를 실행합니다.
3. **정리 확인**: 지저분했던 코드들이 우리 팀의 표준 스타일로 일제히 정렬됩니다.
