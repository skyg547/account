# 🚪 [Tech 11] API Gateway & Resilience4j

### 👶 초보자를 위한 개념 설명
> **API Gateway란 무엇인가요?**
> 마치 **"대형 호텔의 1층 안내 데스크"**와 같습니다. 손님(사용자)이 어떤 서비스를 원하든 일단 정문으로 들어오면, 안내 데스크에서 "뷔페는 3층, 수영장은 5층입니다"라고 길을 안내(Routing)해주고 출입증이 있는지 검사도 합니다.

### 💡 주요 특징 및 예시
1. **Routing**: 여러 개로 쪼개진 서버 주소를 외울 필요 없이, 게이트웨이 주소 하나로 모든 서비스에 접속하게 해줍니다.
2. **Resilience4j (Circuit Breaker)**: 뷔페 식당에 불이 났다면(서버 장애), 안내 데스크에서 미리 "지금 식당 이용이 어렵습니다"라고 말해줍니다. 이렇게 하면 손님이 식당 앞에서 하염없이 기다리다가 호텔 전체가 마비되는 것을 막아줍니다.

### 🚀 실전 사용 가이드 (Step-by-Step)
**[새로운 모듈을 게이트웨이에 연결하기]**
1. **Route 설정**: `api-gateway` 프로젝트의 설정 파일(`yml`)에 새 서비스의 주소와 경로(Path)를 적습니다.
2. **Filter 추가**: "이 주소는 무조건 로그인해야 해"라고 보안 필터를 씌웁니다.
3. **확인**: 이제 사용자가 8080 포트를 통해 접속하면 게이트웨이가 새 서비스를 찾아서 연결해줍니다.

# 🔑 [Tech 12] Auth Service & JWT (JSON Web Token)

### 👶 초보자를 위한 개념 설명
> **JWT란 무엇인가요?**
> 마치 **"놀이공원의 자유이용권 팔찌"**와 같습니다. 입구(로그인)에서 한 번 신원을 확인받고 팔찌를 차면, 매번 민증을 보여줄 필요 없이 팔찌만 보여주고 모든 놀이기구(서비스)를 자유롭게 탈 수 있습니다. 이 팔찌는 특수 재질(암호화)로 되어 있어서 위조가 불가능합니다.

### 💡 주요 특징 및 예시
1. **Stateless**: 서버가 사용자가 누구인지 일일이 기억(세션)하지 않아도, 사용자가 들고 온 토큰만 검사하면 되므로 서버의 부담이 확 줄어듭니다.
2. **Token Relay**: 게이트웨이에서 검사한 토큰을 뒷단 서버들에게도 전달하여, 각 서비스가 안전하게 데이터를 주고받게 합니다.

### 🛠️ 우리 프로젝트에서의 활용
- **보안 일원화**: 모든 서비스마다 로그인 로직을 만들지 않고, `auth-service`에서 토큰을 발급하고 게이트웨이에서 이를 검증하는 중앙 집중형 보안을 구축했습니다.

### 🚀 실전 사용 가이드 (Step-by-Step)
**[로그인 후 보안 구역 이용하기]**
1. **로그인**: 아이디/비번을 보내 `auth-service`에서 JWT 토큰(팔찌)을 발급받습니다.
2. **토큰 보관**: 프론트엔드 브라우저(Cookie나 LocalStorage)에 이 토큰을 소중히 보관합니다.
3. **요청 시 제출**: 다른 데이터를 요청할 때마다 헤더에 이 토큰을 실어 보냅니다.
4. **검증**: 게이트웨이가 토큰을 보고 "진짜 팔찌 맞네!" 하고 승인하면 비로소 데이터가 화면에 나타납니다.
