# Loan Beginner Guide

## 1. 이 모듈을 한 문장으로 설명하면

은행이나 회사가 빌려준 돈을 "언제 얼마 나갔고, 이자는 얼마나 벌었고, 수수료는 기간에 맞춰 얼마나 나눠 인식해야 하는지" 관리하는 모듈입니다.

## 2. 초보자가 먼저 알아야 할 용어

- 원금: 처음 빌려준 돈입니다.
- 명목이자율: 계약서에 적힌 표면 금리입니다.
- EIR(유효이자율): 수수료와 각종 현금흐름까지 반영한 실제 수익률입니다.
- 이연 항목: 지금 한 번에 처리하지 않고 여러 기간에 나눠서 인식할 금액입니다.
- 상각 스케줄: 월별 또는 기간별로 얼마를 이자수익, 원금회수, 이연상각으로 잡을지 적어둔 계획표입니다.
- 중도상환: 만기 전에 일부 또는 전부를 먼저 갚는 것입니다.

## 3. 실무 흐름을 쉬운 말로 보면

1. 대출 계약을 등록합니다.
2. 실제로 돈을 내보내면 실행 기록과 분개를 만듭니다.
3. 취급수수료 같은 금액은 바로 수익/비용으로 다 잡지 않고 이연합니다.
4. 매 기간 EIR 기준으로 이자수익과 이연상각을 계산합니다.
5. 고객이 중간에 조기상환하면 남은 스케줄을 다시 계산합니다.
6. 필요하면 매일 미수이자와 이자수익도 추가로 인식합니다.

## 4. 왜 EIR가 필요한가

명목이자율만 보면 계약서의 금리만 보게 됩니다. 하지만 실제 대출은 수수료, 할인, 중도상환 같은 요소 때문에 실제 수익률이 달라집니다. 이 모듈은 그 차이를 반영하려고 `EIRCalculator`와 `EIRAmortizationSchedule`을 사용합니다.

예시:
- 원금 1,000을 빌려줌
- 실행 시점에 수수료 20을 받음
- 계약서 금리는 5%라도, 실제 수익률은 5%와 다를 수 있음
- 그래서 기간별 수익 인식은 EIR 기준으로 다시 계산함

## 5. 문서를 읽을 때 헷갈리기 쉬운 부분

### `Loan`과 `LoanContract`가 왜 둘 다 있나요?

현재 구현이 한 가지 모델로 완전히 통합되지 않았기 때문입니다.

- `Loan`
  - 대출 생성, 실행, 이연, 재계산 API의 중심입니다.
- `LoanContract`
  - 일별 이자 발생 인식과 소스문서 조회에서 사용됩니다.

초보자는 먼저 `Loan` 흐름을 메인으로 이해하고, `LoanContract`는 보조 레거시/병행 모델로 보는 편이 안전합니다.

## 6. 계정 분개는 어떻게 보나요

대표 예시는 아래처럼 이해하면 됩니다.

대출 실행:
- 차변 `131000`: 대출채권 증가
- 대변 `101000`: 현금/예금 감소

일별 이자 발생:
- 차변 `11501`: 미수이자
- 대변 `41101`: 이자수익

주의:
- 이 계정들은 현재 코드에 고정값으로 들어가 있는 경우가 있습니다.
- 그래서 실제 운영 계정체계와 다르면 별도 정비가 필요합니다.

## 7. 처음 확인하면 좋은 API 순서

1. `POST /api/loan/loans`
2. `POST /api/loan/disbursals`
3. `POST /api/loan/deferred-item-types`
4. `POST /api/loan/deferred-items`
5. `POST /api/loan/amortization-schedules/generate`
6. `POST /api/loan/events`
7. `POST /api/loan/dod-scenario`

## 8. 운영 관점에서 꼭 주의할 점

- 분개 생성 경로가 통일되어 있지 않습니다.
- 일부 계정과목이 하드코딩되어 있습니다.
- 재계산 후 기존 미래 스케줄은 삭제가 아니라 재계산 표시로 남습니다.
- 일별 발생 인식은 `LoanContract`를 기준으로 중복 로그를 막습니다.
