# Loan Beginner Guide

## 1. 이 모듈을 한 문장으로 설명하면

은행이나 회사가 빌려준 돈을 "언제 얼마 나갔고, 이자는 얼마나 벌었고, 수수료는 기간에 맞춰 얼마나 나눠 인식해야 하는지" 관리하는 모듈입니다.

## 2. 초보자를 위한 개념 설명 (Beginner's Concept Explanation)

**대출은 '친구에게 큰 돈을 빌려주고 매달 이자를 받는 것'과 같습니다.**
- **원금 (Principal):** 처음에 친구에게 빌려준 진짜 돈 (예: 1,000만원).
- **명목이자율:** 계약서에 도장 찍을 때 약속한 이율 (예: 연 5%).
- **이연 항목 (Deferred Item):** 돈을 빌려줄 때 수수료 10만원을 미리 뗐다면, 이 10만원을 오늘 한 번에 다 번 것으로 치지 않고 대출 기간 내내 조금씩 나눠서 수익으로 잡는 회계 마법입니다.
- **유효이자율 (EIR):** 수수료와 중간에 돈을 갚는 상황까지 다 합쳐서 계산한 '나의 진짜 수익률'입니다.
- **중도상환:** 친구가 돈이 생겨서 약속한 만기보다 일찍 원금 일부를 갚는 것입니다.

이 모듈은 단순히 돈을 빌려준 기록만 남기는 것이 아니라, **EIR**을 사용해 매일매일 진짜 얼마를 벌고 있는지 수학적으로 계산해 내는 매우 중요한 두뇌 역할을 합니다.

## 3. 핵심 아키텍처 및 기술 표준

- **헥사고날 아키텍처 (Ports and Adapters):** 대출 이자 계산이나 상환 스케줄 같은 핵심 도메인 로직은 가운데에 안전하게 보호되며, 외부 API 호출이나 DB 저장은 `Port`와 `Adapter`를 거쳐 처리됩니다. 변경에 매우 강한 구조입니다.
- **ID 기반 참조 (ID-based references):** 거래처나 연관된 다른 시스템 데이터를 참조할 때는 `business_partner_code` 같은 코드가 아닌 `business_partner_id`라는 고유 식별자만 저장하여 참조 무결성을 높입니다.
- **SCD2 (Slowly Changing Dimensions):** 대출 조건(금리 변경, 만기 연장 등)이 변경되면 과거 스케줄과 대출 정보를 지우지 않고 `valid_from`, `valid_to`, `is_current`를 통해 변경 이력을 차곡차곡 쌓아둡니다.
- **Multi-stage Docker 환경:** 이 거대한 로직을 포함한 앱은 다단계 도커 빌드로 구성되어, 빌드 시점의 불필요한 라이브러리를 제외하고 아주 가볍고 안전한 런타임 이미지로 묶여 서버에 배포됩니다.

## 4. 왜 유효이자율(EIR)이 중요한가?
계약서 이자율만 보면 착시가 생길 수 있습니다. 이 모듈은 수수료나 할인액까지 모두 반영해 실제 돈을 버는 속도(EIR)를 다시 계산하고 그 속도에 맞춰 이자수익과 상각 스케줄을 만들어 냅니다.

## 5. 단계별 실무 흐름
1. 대출 계약을 등록하고 돈을 송금합니다 (실행 분개 생성).
2. 취급수수료 등을 이연 항목으로 잡아둡니다.
3. 모듈이 EIR 스케줄을 쫙 뽑아내서 매달 얼마를 회계상 수익으로 잡을지 결정합니다.
4. 친구가 중도상환을 하면, 남아있는 스케줄을 다시 계산(재계산)하여 업데이트합니다 (이때 SCD2를 통해 과거 내역을 보존).

## 6. 현재 구현에서 주의할 점

- 대출 계약 정보는 `Loan` 모델에 통합되어 별도 계약 테이블을 사용하지 않습니다.
- 자동 전표에 쓰는 계정코드는 설정 파일의 `account.loan.accounting.*` 값이 반드시 필요합니다.
- 설정이 빠져 있으면 임의 기본 계정으로 전표를 만들지 않고 오류로 중단합니다.
